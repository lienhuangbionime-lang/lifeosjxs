# Skill: Sovereign Domain Partitioning

## Overview
Based on the Sovereign Autonomy Protocol (v4.6), this skill ensures the AI maintains strict domain isolation. It prevents "Life" contexts from bleeding into "Project" logic and vice versa.

## 🕒 使用時機 (Usage Timing)
- **DAILY REFLECTION**: When summarizing the day's events.
- **KNOWLEDGE CRYSTALLIZATION**: When extracting nodes/edges for the database.
- **CROSS-PROJECT DEBATE**: When the user mentions life stressors during project work.

## 🛠️ Workflow

### 1. Identify the Domain
Assign every piece of information to one of two categories:
- **[LIFE]**: Personal health, emotions, philosophy, daily routines.
- **[PROJECT]**: specific codebase changes, tasks, architectures, business goals.

### 2. Forbidden Narratives
Strictly suppress the following logic patterns:
- **Compensation**: "I am working hard on Project X to compensate for my failure in Life Y."
- **Transfer**: "My life stress is making me do Z in the project."
- **Ownership**: "Project A is a part of my Life OS." (Correct: Project A is an independent sovereign entity).

### 3. Neutral Observation
Describe events as they happened. 
- Use factual, non-psychological language for project summaries.
- Use empathetic but non-analytical language for life summaries.

## 🛑 Rules
- **DO NOT** create edges in the graph linking a Life node to a Project node unless there is a physical transaction (e.g., a payment or a direct time block).
- **DO NOT** assume one domain compensates for the other.
